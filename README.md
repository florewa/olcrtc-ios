# olcRTC for iOS

Нативный SwiftUI-клиент olcRTC для iPhone и iPad. Приложение запускает Go-ядро
olcRTC, подключается к серверу через поддерживаемый WebRTC-медиасервис и
поднимает защищённый локальный SOCKS5 на `127.0.0.1:18080`.

Для системного туннеля используется отдельное приложение с Packet Tunnel,
например Happ. Встроенного `NetworkExtension` здесь нет, поэтому специальный
Apple entitlement и платный Developer Program для сборки клиента не нужны.

Сервер и панель управления находятся в
[`florewa/Olcrtc_manager`](https://github.com/florewa/Olcrtc_manager).

## Возможности

- импорт полного и compact-формата `olcrtc://`;
- `telemost`, `wbstream` и `jitsi`;
- `vp8channel` и `datachannel`;
- постоянные HTTPS-подписки `/sub/<slug>`;
- вставка и открытие `olcrtc://subscription?...` bootstrap-ссылок;
- AES-256-GCM fallback подписок через Yandex Disk;
- автоматическое обновление подписок;
- хранение профилей, ключей и SOCKS-учётных данных в iOS Keychain;
- случайные логин и пароль локального SOCKS5;
- экспорт совместимой SOCKS-конфигурации для Happ;
- TCP и SOCKS5 UDP Associate;
- восстановление carrier-соединения и контроль его состояния;
- end-to-end watchdog с автоматическим перезапуском зависшего Go-ядра;
- сохранение последней выбранной конфигурации;
- однократный мастер импорта в Happ и быстрый переход к следующим запускам;
- Liquid Glass на iOS 26 и material-интерфейс на iOS 16–18;
- best-effort background audio keep-alive для sideload-сценария;
- сборка unsigned IPA на GitHub Actions без собственного Mac.

## Как это устроено

```text
приложения iPhone
  → Happ Packet Tunnel
    → SOCKS5 127.0.0.1:18080
      → olcRTC iOS
        → шифрованный VP8/WebRTC-медиаканал
          → Telemost, WB Stream или Jitsi
            → olcRTC server
              → интернет
```

Happ перехватывает системный трафик и передаёт его локальному SOCKS5. olcRTC
мультиплексирует соединения, шифрует их и отправляет как медиапоток участнику
той же комнаты на VPS. Сервер распаковывает поток и открывает конечные TCP/UDP
соединения.

## Требования

- iOS/iPadOS 16 или новее;
- совместимый сервер `server-v1.9.72` или новее;
- Happ или другой клиент, способный направить системный трафик в локальный
  SOCKS5;
- IPA, подписанный вашим Apple ID при установке;
- HTTPS с публично доверенным сертификатом для обычного URL подписки.

Самоподписанный сертификат подписки намеренно не принимается. Можно
использовать bootstrap-ссылку с зашифрованным Yandex Disk mirror, но саму
ссылку следует хранить в секрете: она содержит ключ расшифровки.

## Установка IPA без Mac

1. Откройте **Actions → Build unsigned iOS IPA**.
2. Запустите workflow с `core_ref=server-v1.9.73`.
3. Дождитесь успешной сборки и скачайте artifact `olcrtc-ios-unsigned`.
4. Сверьте SHA-256 с файлом из artifact.
5. Установите IPA через Sideloadly на Windows, подписав его своим Apple ID.

Бесплатная персональная подпись Apple обычно действует семь дней, после чего
приложение требуется переподписать. Это ограничение Apple, а не olcRTC.

Готовый unsigned IPA нельзя установить простым открытием файла: перед
установкой он обязательно должен быть подписан для конкретного устройства.

## Настройка сервера

Установите manager на Linux VPS:

```bash
curl -fsSL https://raw.githubusercontent.com/florewa/Olcrtc_manager/master/server-install/olcrtc-setup.sh | sudo bash
```

В Admin UI:

1. Создайте инстанс `wbstream + vp8channel` или `telemost + vp8channel`.
2. Укажите существующую комнату провайдера.
3. Дождитесь `Link connected`.
4. Создайте подписку и добавьте инстансы через кнопку **Состав**.
5. Скопируйте HTTPS URL подписки либо приватную bootstrap-ссылку кнопкой
   **Ссылка**.

Панель генерирует отдельные ключи и `client_id` автоматически. Не встраивайте
рабочие профили непосредственно в исходный код или IPA.

## Использование на iPhone

1. Установите Happ из App Store.
2. В olcRTC нажмите `+` и добавьте HTTPS URL подписки, bootstrap-ссылку или
   отдельный `olcrtc://` профиль.
3. Выберите конфигурацию и нажмите **Запустить туннель**.
4. Дождитесь состояния подключения.
5. При первом запуске нажмите **Скопировать для ИМПОРТА**.
6. В Happ выберите `+ → Import from clipboard` и включите импортированный
   профиль.

Повторно импортировать SOCKS-профиль не нужно. В следующие разы сначала
запустите olcRTC, затем нажмите **Перейти в Happ** и включите уже сохранённую
конфигурацию.

olcRTC необходимо запускать до Happ. Не закрывайте olcRTC свайпом из списка
последних приложений: iOS сразу остановит локальный SOCKS и WebRTC-соединение.

Watchdog проверяет control pong, который проходит через весь зашифрованный
RTC-канал до сервера. После двух последовательных неудачных проверок клиент
останавливает зависшее ядро и делает до трёх попыток восстановления на том же
SOCKS-порту. Happ обычно переподключается автоматически. Если его старые
соединения остались зависшими, достаточно выключить и снова включить профиль
Happ — повторный импорт не требуется.

Если автоматическое восстановление не удалось:

1. выключите профиль Happ;
2. вернитесь в olcRTC и переподключите туннель;
3. снова включите Happ.

Порт `18080` выбран намеренно. `10808` зарезервирован внутренним Xray в Happ и
приводит к ошибке «порт уже занят».

## Подписки

Обычный URL:

```text
https://server.example:8443/sub/random-slug
```

Bootstrap deep link:

```text
olcrtc://subscription?url=...&name=...&mirror_type=yandex_disk&mirror_url=...&mirror_key=...
```

Bootstrap-ссылку можно открыть как deep link или вставить непосредственно в
поле добавления подписки. Параметры должны быть разделены символом `&`.

При обновлении сначала запрашивается основной HTTPS URL. Если запрос не удался
и настроено зеркало, клиент скачивает зашифрованный файл с Yandex Disk и
расшифровывает его локально.

## Фоновая работа

Приложение использует беззвучное аудио и `UIBackgroundModes=audio`, чтобы iOS
не замораживала процесс сразу после перехода в Happ. Это best-effort механизм,
а не системная VPN-гарантия.

Фоновое соединение может быть остановлено:

- принудительным закрытием приложения;
- нехваткой памяти;
- телефонным/VoIP-звонком или сменой аудиосессии;
- энергосбережением и внутренними решениями iOS;
- истечением подписи sideload-приложения.

## Локальная сборка на macOS

Требуются Xcode, Go 1.25+, XcodeGen, `gomobile` и `gobind`:

```bash
brew install xcodegen
go install golang.org/x/mobile/cmd/gomobile@v0.0.0-20260410095206-2cfb76559b7b
go install golang.org/x/mobile/cmd/gobind@v0.0.0-20260410095206-2cfb76559b7b
sh Scripts/test-ios.sh
sh Scripts/build-ipa.sh ../Olcrtc_manager
```

Результат: `build/olcrtc-ios-unsigned.ipa`.

## Безопасность

- Профили и подписки хранятся в Keychain с
  `AfterFirstUnlockThisDeviceOnly`.
- Репозиторий и стандартная IPA не содержат рабочих комнат, ключей или
  токенов.
- `olcrtc://` URI, URL подписки, QR и bootstrap-ссылка являются секретами.
- Не публикуйте логи и скриншоты, если на них видны профили или ключи.
- При утечке ротируйте ключ и `client_id`, а для подписки создайте новый slug.

## Ограничения

- Нет встроенного Packet Tunnel и публикации в App Store.
- UDP проходит через надёжный KCP-канал, поэтому потери восстанавливаются ценой
  дополнительной задержки.
- Скорость зависит от оператора, медиасервиса, комнаты и расположения VPS.
- Доступность внешних provider API не контролируется проектом.
- Соблюдайте применимое законодательство и условия используемых сервисов.
